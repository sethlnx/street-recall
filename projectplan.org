#+title: Project plan
* Goal
Learn street names from a map with the current street's name hidden, hosted on GitHub Pages.

* Implemented: Pendleton and Portland, Oregon
- Highlight one street, think or type a guess, then reveal its name.
- Street names are hidden by default. “Show other street names” remains optional; an explicitly saved choice is remembered.
- The current street is excluded from map labels until you reveal the answer. Labels update for each new question and when zooming or panning.
- Labels are abbreviated (for example, =SE Division St=) and rotated along visible, connected, sufficiently straight road sections. Zoom in to show shorter streets; labels that cannot fit or would overlap are omitted.
- Grade your own recall: Again, Hard, Good, or Easy. Spelling is not checked.
- Review due streets before introducing new ones.
- Save schedules in =localStorage=, not cookies. No backend or account.
- The top-right “Study city” dropdown switches between Pendleton and Portland. The last successfully loaded city is remembered; a first visit starts in Pendleton.
- Reviews, selected areas, label preferences, and visit counts are separate per city. Existing Pendleton storage keys and ratings are retained. Unsaved in-memory reviews survive city changes during the same page visit.
- Choose any combination of the active city's study areas, then press “Apply study areas.” Pendleton has six geographic areas and defaults to Downtown. Portland has three official police precincts and defaults to Central Precinct.
- Area changes replace the current question and filter the due/new queue without deleting any saved ratings. Streets shared by areas are one card with one shared schedule.
- Pendleton introduces major throughways (primary, secondary, and tertiary corridors) and central areas first—leading with Downtown, then central Pendleton neighborhoods, and finally outer West & airport and rural unclassified roads—while Portland introduces major named arterials before major numbered roads and named collectors. Within each tier, longer corridors in the selected areas come first; due reviews still take precedence over new cards.
- Selected areas choose which streets are in the deck, while the full mapped street (for example, all of =Northeast Halsey Street=) is highlighted. Other roads remain visible for geographic context.
- The map focuses on the current street. Drag to pan and use the zoom buttons; reset shows the full extent of the selected areas.
- Keyboard: Enter reveals from the guess field; 1–4 rate the revealed answer.
- When every selected street has been introduced, wait until a selected review is due. The open page checks every 15 seconds. Due streets outside the selected areas do not enter the queue.
- Browser storage failures show a warning; unreadable saved data is not overwritten.
- City changes cancel older map requests and disable reviews until the chosen dataset is loaded. A failed load cannot record a rating against the previous city's streets; another city can still be selected.

* Run locally
From this directory:
#+begin_src sh
python3 -m http.server 8765 --bind 127.0.0.1
#+end_src
Open [[http://127.0.0.1:8765/][the study app]]. Opening =index.html= directly does not support the module/data loading.

* Publish on GitHub Pages
1. Commit these files to the repository.
2. In the repository's Settings → Pages, choose “Deploy from a branch.”
3. Select the branch containing the app and the =/ (root)= folder.
4. Open the URL GitHub provides after deployment.

All app/data URLs are relative, including under a repository subpath. No package installation, build step, external map tiles, API key, or runtime third-party requests are required. =.nojekyll= keeps this a plain static site.

* Review scheduling
=scheduler.mjs= implements a small SM-2-inspired algorithm, not Anki's FSRS algorithm or Anki synchronization.

| Rating | New/learning street | Mature review |
|--------+---------------------+---------------|
| Again  | 1 minute            | 1 minute; return to learning |
| Hard   | 6 minutes           | Previous interval × 1.2 |
| Good   | 1 day               | Previous interval × ease |
| Easy   | 4 days              | Previous interval × ease × 1.3 |

Ease starts at 2.5, decreases for Again/Hard, increases for Easy, and never drops below 1.3. An interval shorter than one day is a learning step. Names and geometry are bundled; review due times use the device's clock.

Progress is separate for each browser and origin. It does not sync between devices or between localhost and GitHub Pages. Clearing site data removes it. Use one study tab at a time; simultaneous tabs can overwrite each other's reviews.

* Street dataset and licensing
** Pendleton
- =data/pendleton.json=: 251 unique named streets across latitude 45.639–45.712 and longitude -118.882–-118.7495, covering broader Pendleton including the airport area.
- OpenStreetMap snapshot: 2026-10-30T00:01:15Z.
- Each exact full street name is one card; directional names remain separate. The exception is one road mapped under two spellings: a name and the same name with a direction prefix, or a hyphenated name in reverse order, whose lines meet (for example =Pendleton-John Day Highway= and =Southwest Pendleton-John Day Highway=, or =Oregon-Washington Highway= and its one-way =Washington-Oregon Highway= carriageway). Those are one card named for the longer mapped road. Two different prefixes (=Southeast X=, =Southwest X=) are never merged, and a plain name that meets two different prefixes is left alone. A street can contain multiple mapped segments and occur in several areas. Counts per area therefore do not sum to the unique total. Continuous corridors that OpenStreetMap splits across shared highway concurrencies (such as =Oregon-Washington Highway= along =Southeast Court Avenue=, =Airport Road= along =Northwest A Avenue=, and =Rieth Road= along =Main Street=), sub-90-meter area corners (such as =Southwest Emigrant Avenue= and =Southeast Dorion Avenue=), colinear unnamed links, and short cross-street doglegs are reconnected into continuous highlight polylines.
- Cards include named primary, secondary, tertiary, residential, unclassified, and living-street ways with at least 90 meters of geometry in an area. Service roads and paths provide context but are not cards.
- Source: [[https://www.openstreetmap.org/][OpenStreetMap]], retrieved using [[https://overpass-api.de/][Overpass API]]. Road and river geometry are clipped to the study coverage.
- Map data © OpenStreetMap contributors. The bundled derived street database is available under the [[https://opendatacommons.org/licenses/odbl/1-0/][Open Database License 1.0 (ODbL)]]. See [[https://www.openstreetmap.org/copyright][OpenStreetMap copyright and attribution]].
- The map is a bounded study diagram, not a live navigation map. Long streets are shown only within the study boundary.

Pendleton areas are geographic study rectangles, not official neighborhood or municipal boundaries. All 33 original downtown street IDs remain available, preserving existing schedules.

New-card introduction order:
1. Primary throughways (Downtown first, then central Pendleton, then West & airport).
2. Secondary throughways (Downtown, central Pendleton, West & airport).
3. Tertiary collectors (Downtown, central Pendleton, West & airport).
4. Downtown multi-area throughways, then Downtown single-area streets.
5. Central Pendleton multi-area throughways, then central neighborhood streets.
6. West & airport residential streets.
7. Outlying rural and airport industrial unclassified roads.

Within each tier, longer mapped corridors in the selected study areas come first. Equal-length ties are shuffled; reviewed/future cards are skipped and due reviews still lead. =tools/pendleton-study-policy.mjs= defines the tiers; =study.mjs= applies selected-area corridor ranking.
Refresh the bundled data with:
#+begin_src sh
node tools/update-map.mjs
#+end_src
This maintenance command requires a live Overpass connection; studying does not. An unavailable or incomplete Overpass response fails without replacing the bundled dataset.

** Portland: Police precincts
=data/portland.json= contains 393 study cards, pruned from 2,447 street names. All 2,447 names remain available as map context/optional labels. Streets shared by precincts are one card within Portland and use one schedule.

| Police precinct | Eligible streets |
|-----------------+------------------|
| Central         |              218 |
| North           |              159 |
| East            |               91 |

- Boundaries come from the City's [[https://www.portlandmaps.com/arcgis/rest/services/Public/CGIS_Layers/MapServer/18][Portland Police Districts GIS layer]], grouped by =PRECINCT=: =CE=, =NO=, =EA=. The [[https://www.portland.gov/police/divisions/precincts][Police Bureau precinct overview]] describes Central, North, and East.
- All 60 official district features are retained, with 20 assigned to each precinct. Streets are clipped against polygon unions, including holes and disconnected parts; bounding rectangles are used only to frame the map, not assign streets.
- Official boundary retrieval: 2026-10-30T00:02:51.887Z. OSM snapshot: 2026-10-30T00:02:20Z. These are independently dated sources; precinct boundaries can change after retrieval.
- Study eligibility uses OSM primary/secondary arterials and named tertiary collectors. Residential, unclassified, living-street, and numbered tertiary roads are excluded from cards, not from map context. Major numbered primary/secondary roads (including 82nd and 122nd) remain.
- A street needs at least 90 mapped meters of its qualifying major class inside Portland and at least 90 meters of named geometry in a precinct. Retained names keep their full precinct-clipped geometry, including any local portions of the same street.
- Removed cards' browser review records are left untouched but no longer enter the Portland queue. Map context still includes local roads, arterials, and freeways; service/parking roads and paths are omitted. Rivers are centerlines rather than water-surface polygons.
- Street data © OpenStreetMap contributors, under ODbL 1.0. Official boundary attribution: City of Portland / Portland Police Bureau. This is a study map, not an official police, legal-boundary, or navigation tool.
- The Portland JSON is approximately 12.7 MB uncompressed and is fetched only when Portland is selected. The browser needs no live GIS/OSM API for study sessions.

Refresh Portland's bundled data with:
#+begin_src sh
node tools/update-portland.mjs
#+end_src
The generator fetches official district polygons and OSM roads, clips exact geometry, and atomically replaces the dataset only after successful generation. Source URLs, retrieval dates, road classes, and limitations are recorded in the bundle.

New-card introduction tiers:
1. Named primary arterials.
2. Named secondary arterials.
3. Numbered primary arterials.
4. Named tertiary collectors.
5. Numbered secondary arterials.

Within each tier, longer mapped corridors in the selected precincts come first. Equal-length ties are shuffled; reviewed/future cards are skipped and due reviews still lead. =tools/portland-study-policy.mjs= defines eligibility and tiers; =study.mjs= applies selected-area corridor ranking. The data refresh command reapplies the policy.

* Map rendering
- =map-scene.mjs= projects and spatially indexes road polylines. Viewport queries retain crossing roads and shared junctions; zoom-banded simplification stays below the requested subpixel error.
- =map-renderer.mjs= paints background roads and labels with native Canvas 2D. SVG contains only the unsimplified highlighted street and accessible map title, not citywide road/label paths.
- Pan/zoom updates are coalesced into one animation frame using the latest camera state. Input handlers do not measure or rebuild SVG labels.
- One bounded, roads-only bitmap extends 25% beyond each viewport edge. Ordinary pans translate the bitmap; zoom, resize, DPR changes, or leaving its extent rebuild it from the spatial index.
- Label geometry is initialized only when names are enabled. Canvas text measurements are cached, and collision checks use a screen-space grid instead of DOM layout.
- Labels are never part of the cached road bitmap. The current street's name mask and SVG highlight update in the same frame, avoiding stale-name flashes when changing cards.
- Canvas and SVG use the same projection and letterbox transform. Raster density is capped at DPR 2; resize and display-density changes invalidate the background cache.
- City switches cancel pending renderer frames, disconnect observers/listeners, clear old graphics, and release the cached bitmap.

Measured in managed Chromium at a 1365×1050 viewport, using the same 30-move drag before/after:

| Label setting | Task CPU before (ms) | Task CPU after (ms) |
|---------------+----------------------+---------------------|
| Names hidden  |                  143 |                  43 |
| Names shown   |                  504 |                 179 |

With names shown, layout passes fell from 13,167 to 30. The SVG went from 2,475 paths to one. These are browser smoke measurements, not a frame-rate guarantee for every device. Portland's initial bundled-data download remains approximately 12.7 MB uncompressed.
